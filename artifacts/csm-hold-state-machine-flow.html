状态每周期重新计算

每周期从 NotActive 开始，按固定顺序处理六类服务。它不是只允许相邻跳变的传统状态机。

NEGATIVE WINS

目标越负，制动请求越强。

TIE ORDER

相等时 BrakeHold 可覆盖 DriveOff，DriveOff 可覆盖 Deact。

ROLLPREV OVERRIDE

RollPrev Active 后无条件覆盖普通候选。

FINAL CLAMPS

HW limit → BrkHold；请求无效 → NotActive。

状态条件速查

用于测量回放时判断进入、保持和退出原因。

target 越负 = 制动越强
0FALLBACK / FORCE

NotActive

没有有效负目标，且没有 TorqueBalance 特殊保持。

  • target ≥ 0
  • Plain Ramp ≤ 1
  • PostCore 无效时强制进入
1NORMAL / LIMIT

BrkHold

常规 Hold 候选胜出，或触发硬件/热限制。

  • Hold Active
  • holdTarget ≤ 当前 target
  • 等于 limit 也覆盖
2TRANSITION

HoldForDriveOff

DriveOff 已请求，但释放算法尚未接管。

  • DriveReq > 0
  • 已有 BrkHold 或 Rollout
  • DriveOff Active=false
3PRESSURE BUILD

BrkInc

Rollout 或 BrakeIncrease 产生更强目标。

  • 候选必须严格更负
  • 目标达到后退出
  • 热限制会终止
4OVERRIDE

RollPrev

车辆仍运动且防溜延时到期。

  • BrkHold Active
  • VehStop=false
  • TRollPrevDelay ≤ 0
5STICKY MODE

DriveOffTrqBal

TorqueBalance 使用 WithBrkInc 模式。

  • TorqueBalance 类型
  • WithBrkInc 模式
  • K1 可维持状态
6RELEASE

DriveOff

ComfortRelease、TorqueSufficient 或无增压 TB。

  • DriveOff Active
  • 候选 target 胜出
  • 目标归零后退出
7RELEASE

Deact

Release 请求激活，释放候选胜出。

  • DeactReqActive > 0
  • deactTarget ≤ 当前 target
  • 后续服务仍可覆盖
04

实现审查提示

建议结合实车测量确认。

重点核查
A

DriveOff service bit 疑似写反

TorqueSufficient Active 写入 ComfortRelease ID；ComfortRelease Active 写入 TorqueSufficient ID。

B

TorqueBalance 注释与代码顺序不一致

注释称 TorqueBalance 优先，实现顺序却是 ComfortRelease → TorqueSufficient → TorqueBalance。

C

DriveOffTrqBal K1 条件重复

特殊保持分支连续两次检查相同的 K1 状态。

D

BrkHold 可能是限制覆盖结果

HW/Thermal limit 会把其他业务状态最终统一标记为 BrkHold。
