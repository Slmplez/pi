修复建议

必须：DriveOff 全局优先

将 `!req_DriveOff` 放到 Hold OR 条件外，禁止 Cust 和 ADS 路径绕过驾驶员起步请求。

必须：AEB 接管一次性消费

增加 `takeoverEligible/consumed` 锁存。DriveOff 后，本次 AEB 事件不得再次产生 Cust Hold。

建议：重入抑制

等待 `CSMHoldState==NotActive` 稳定，并检测到新的 AEB 请求边沿后，才允许重新接管。

先定位再处理 APB

不要直接屏蔽 MechHold。若为 P 挡，检查挡位信号；若为 RollPrevOver，检查计数是否跨重入错误继承。

推荐仲裁结构

trig_Hold = HoldCoreConditions
         && !CustCondDisableHold
         && !trig_Release
         && !req_DriveOff
         && (StandardBrakePath
              || CustTrigHold
              || ADSRequestAVH_Trigger);

AEB 接管生命周期

AEB Hold 新事件       -> takeoverEligible = true
AVH 成功接管一次      -> takeoverEligible = false
DriveOffRequested      -> takeoverEligible = false
AEB 撤销并出现新边沿  -> 允许下一次接管
不推荐：仅提高 `C_AVH_DGearActivationPressure`。这只能降低踏板路径敏感性，不能修复 CustTrigHold 重入。

最终判断

  • AVH 反复激活：高置信度根因是 `CM_AVH_CustTrigHold` 持续请求绕过 DriveOff，并缺少 AEB 事件消费与重入抑制。
  • APB Apply：已确认由 MechHold 路径发出；P 挡 `CustTrigTakeOver` 有直接图形线索，必须和 `RollPrevOver` 同步测量。
  • 标定阈值：`C_AVH_DGearActivationPressure=0` 是次要敏感性风险，不是主修复点。
