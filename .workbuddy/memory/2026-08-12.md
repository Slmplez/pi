## ASCET C 代码生成 ToolAPI 分析（结合 AscetAPI_KnowledgeBase）

- 用户要求分析"生成 C code 的接口 API"，知识库位于 `C:\Repo\Copilot\AscetAPI_KnowledgeBase`（extracted_chm 有 3961 个 ToolAPI HTML 文档，源自 Etas.AscetNET 6.1.4.0）。
- ToolAPI 代码生成面分三层：
  - 执行：`CodeComponent.GenerateCode()` / `GenerateCodeWriteErrorsToPath(path)` / `GenerateCodeForOfflineExperiment*()`；导出生成物 `FileOutGeneratedCodeFlat/Recursive(path)`。
  - 配置：`AscetProject.GetAllCodeGenerators/GetCurrentCodeGenerator/SetCurrentCodeGenerator`；`CodeGenerator.SetCodeGeneratorSetting(name, value)` / `GetValuesForCodeGeneratorSetting` / `SetCurrentCodeExpander`；Is* 谓词（Controller/Implementation/Physical/Quantized）。
  - 诊断/消息：`Ascet.Add/ClearCodeGenMessages`、`WriteCodeGenerationErrorsToPath`；`AscetProject.WriteCodeGenMessagesToXMLFile/ReadCodeGenMessagesFromXMLFile`、`WriteASAP2WithoutCodeGenerationToFile`、`GenerateIntecrioCode`。
- 句柄获取：`AscetDiagram.GetCodeComponent()` / `AbstractBlockDiagramElement.GetCodeComponent()` / `AbstractStateMachineElement.GetCodeComponent()`。权限要求：Read + Generate Code。
- 现状结论：当前 ascetcli（C#）与 ascet-extension（TS）**未封装任何 codegen API**——现有 "code" 工具只覆盖 ESDL 方法体读写（`Method.GetCode/SetCode`）和 module header/external-C 片段（TextCodeWriteService），与 ASCET 的 C 代码生成是两条不同路径。GenerateCode 是候选新工具方向。

## ascet_codegen 工具套件设计（已输出给用户，待确认后实现）

- 形态：单一 canonical 工具 `ascet_codegen`（multi-action，对齐 ascet_read/ascet_edit 模式），7 个 action：
  - 读侧：`list_generators` / `get_generator_settings` / `get_codegen_errors` / `export_generated_code`（FileOutGeneratedCode*，仅需 Read 权限，不重生成）
  - 写侧：`set_generator`（SetCurrentCodeGenerator + SetCodeGeneratorSetting + SetCurrentCodeExpander）/ `generate_code`（GenerateCodeWriteErrorsToPath，强制 DB commit，走 approval 门）/ `export_a2l`（WriteASAP2WithoutCodeGenerationToFile）
- 架构分层：TS runner（`codegen-*.ts`，runAscetCliJson）→ route-manifests/command-aliases → C# `AscetCli/Ascet*Codegen*.cs` → `AscetCopilot/AscetCodegenDomain.cs`（CodegenService，session 复用参考 SetMethodCodeInSession）。
- 关键安全点：generate_code 会强制 commit DB → 复用 edit/approval.ts 确认流 + editability 前置检查；verification 无法 readback，改为 error 文件零错误 + 导出产物 manifest（文件清单+hash）作为证据落盘。

## 关键事实修正：代码生成的执行单元是 CodeComponent，不是 Project

- `AscetProject` **没有** GenerateCode；project 级只有配置类 API（Get/SetCurrentCodeGenerator、build settings XML、codegen messages）和产物类（GenerateIntecrioCode、WriteASAP2*）。
- 生成执行在 `CodeComponent`：`GenerateCode()`（生成并存库）/ `BuildAll()`（生成可加载代码=完整 build，成功后存库）/ `FileOutGeneratedCode*` / `FileOutGenericCodeForExternalMake*`。
- CodeComponent 句柄来自图：`AscetDiagram.GetCodeComponent()`（每个 class/module/statemachine 的 diagram 都有）；GUI 里"对整个 project 生成"实质是对顶层组件递归（FileOutGeneratedCodeRecursive）。
- 设计影响：generate_code <component-path> 的设计正确；如需"project 级生成"= 对 main component 递归；P2 可加 build_all 变体（对应 Build → loadable code）。
