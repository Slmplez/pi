ascet-full-check 工作流与检查能力

一个面向 ASCET 组件、方法、图、BDE 信号映射和引用关系的可扩展检查框架。

/ascet-full-check
status -> scope -> evidence -> check -> verify -> report
3分层职责
5首批规则
8专用 agents

目标不是一次性脚本，而是后续能持续加规则、换工具、扩 agent 的检查平台。

workflow

从问题到报告的执行链路

Ask目标、范围、规则、验证深度、输出格式不清楚时调用 ask_user_question。
Status先跑 ascet_status，必要时查 scheduler 状态。
Scope解析 component、method、diagram、BDE surface。
Plan加载 rule-index，生成 check-plan。
Countcheck_item_count 统计待查对象，不只是 class。
Mode小于 5 inline；大于等于 5 可启用 subagent。
Preflight检查 agent tools 是否包含所需 ascet_*。
Evidence按 tool-map 收集 JSONL 证据并复用。
Checkchecker agents 基于证据输出 JSONL findings。
Report验证高风险发现，合并 Markdown 和 JSON 报告。
关键边界实时 ASCET 查询与规则判断解耦
subagent dispatch gate

live ASCET 任务只发给有工具权限的 agent

允许承接 live evidence

ascet项目本地 fallback，具备 ASCET read-only 工具。
ascet-discovery解析范围、目标清单、组件和图面。
ascet-evidence收集 reusable evidence，避免重复 live 调用。
ascet-verify-checker验证高风险或不确定 findings。

禁止错误分派

  • 不能把 live ASCET evidence 任务发给 builtin reviewer、worker、planner、researcher。
  • 分派前必须比对任务需要的 ascet_* 与 profile tools:。
  • 缺任何工具就不派发，改用 approved agent 或 parent inline。
  • BDE 图读取统一使用 ascet_read action read_block_diagram。
解决的问题避免 reviewer 无 ASCET 工具导致 intercom 卡住
check items

首批规则覆盖哪些检查项目

rule id family severity 检查内容 checker
signal.unused-local-variable signal-variable high 局部变量、signal、occurrence 证据交叉判断未使用或异常使用。 ascet-rule-checker
implementation.missing-final-else condition-loop medium 方法代码和 implementation 中缺少最终 ELSE 或默认赋值路径。 ascet-rule-checker
semantic.position-variable-mapping semantic high 位置变量映射、命名、代码使用与 element metadata 不一致。 ascet-semantic-checker
reference.unexpected-external-used-by reference medium 组件引用、元素引用、occurrence 与外部 used-by 异常关系。 ascet-reference-checker
bde.signal-mapping-mismatch bde-signal-mapping high BDE 连线、信号、端口方向、代码使用之间的映射错误。 ascet-bde-signal-checker
扩展方式新增规则优先改 rule-index.yaml

父 agent 解析组件、方法、图、BDE 连线、signals、references，写入可复查的 scope manifest。

ascet_explore.*

3. 规则计划

从 rule-index.yaml 读取规则，展开成 rule-target pairs，并计算 check_item_count。

rule-index.yaml
check-plan.json
check_item_count

4. 证据缓存

按 tool-map 采集 JSONL evidence。相同 target 的证据复用，失败和 unsupported 也记录。

evidence/*.jsonl
tool + action + target
ok / error
证据进入 checker rule checker、semantic checker、reference checker、BDE checker 只读 evidence 文件，避免每个 checker 重复访问 live ASCET。
finding 进入 merge / verify 每条 finding 带 rule_id、severity、target 和 evidence_id；高风险或不确定项再由 verify checker 调用 ascet_verify、ascet_read、ascet_diff。
数据原则live data 先证据化，再规则化，最后报告化
multi-agent interaction

多 agent 交互：parent 编排，子 agent 专职

Parent agent

负责询问用户、运行 status、发现 scope、生成 plan、计算 check_item_count、执行 profile preflight。

只把 live ASCET evidence 任务交给具备 ascet_* tools 的 approved agent。
如果 check_item_count < 5，直接 inline 完成同样的 evidence 和 report contract。

ascet-discovery

读取 live ASCET 状态和结构，输出 scope-manifest 的候选目标。

ascet-evidence

按 tool-map 采集 code、diagram、reference、diff 等证据，写入 evidence JSONL。

rule / semantic / reference / BDE checkers

读取 evidence 文件，按 rule-index 输出 findings，不直接访问 live ASCET。

ascet-verify-checker

对 high severity 或低 confidence findings 做 readback、diff、verify。

ascet-report-merge

去重、排序、合并 evidence IDs，生成 Markdown 和 JSON 报告。

what it enables

实现的功能总结

完整 ASCET 检查入口

提供 /ascet-full-check 命令，能从模糊请求收集参数并进入标准检查流程。

规则驱动检查框架

规则、证据、报告、扩展方式拆到 references，避免把检查逻辑写死在入口。

大范围任务自动分派

check_item_count >= 5 时启用 subagent，少量对象则 parent inline。

ASCET live 工具门禁

只允许具备 ASCET 工具的 agent 获取实时证据，防止 generic reviewer 卡在 intercom。

BDE 信号映射检查

新增 BDE signal mapping mismatch 规则，读取 block diagram、signals、children、code 和 refs 证据。

可审计报告产物

每条发现都带 evidence_id、tool、action、target，后续能验证、复查、去重和追踪。

ASCET full-check可扩展检查框架，而不是一次性检查脚本
