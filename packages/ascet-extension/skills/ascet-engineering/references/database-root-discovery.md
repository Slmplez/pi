# Database Root Discovery

Bind stored Tree, catalog, Project-closure, or export evidence to the exact live database identity that produced it. A changed `database.name` invalidates prior artifacts even when `database.path` is unchanged. Report identity inconsistencies and never mix evidence from different databases.

Start from the user-supplied target, feature semantics, or known scope. Use `ascet_search.search` for bounded name candidates and `ascet_get.tree` only for hierarchy expansion. Use `ascet_get.formulas` only after resolving one exact Project. Exact Project, Class, Module, Method, path, or OID work does not require a complete database scan.

Known Customer, Package, Library, CNMS, and Platform roots are heuristics, not a universal schema. Preserve exact path spelling. Use object kind, Project topology, OID, references, and interface semantics when conventional roots are absent.

Check `count`, returned items, and `more=true`. Partial evidence cannot prove absence. Stored grep or reverse-reference hits are candidates and require exact live validation before ownership or mutation decisions.
