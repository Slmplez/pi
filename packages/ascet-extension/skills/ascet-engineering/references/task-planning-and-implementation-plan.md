# Task Planning and Implementation Plan

Use 1–2 todolist items for an exact-target read or single-field operation, usually 3–5 for routine ESDL/Element changes, and additional items only for real dependencies, authorization boundaries, or independent write units. For non-trivial work, use milestones such as: confirm scope/target/success criteria; read Signal Flow/current implementation/Elements/Parameters; produce and review the complete implementation plan; run preflight and authorized writes; report changed and unchanged scope.

Before preflight, include: requirement and safe defaults; scope/ownership and exclusions; source → transform → consumer and reuse; exact Method/ESDL patch; Element and Parameter metadata; dependency/mappings/variants; write order; assumptions, blocking unknowns, and risks. Do not create vague “analyze/modify” items or mechanically split every read.
